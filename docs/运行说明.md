# 如何运行和演示

## 先看结构，不加载模型

```bash
python pipeline.py list
python pipeline.py verify
python pipeline.py demo
```

`demo` 是明确标记的 CPU 教学例子，展示错误率、删除代价和统计分母，不是新实验结果。

## 设置机器路径

服务器上：`python pipeline.py prepare --mapping paths.server.json`。
新机器上：复制 `paths.example.json` 为自己的映射文件，填写 `<SET_...>` 后运行 prepare。
prepare 从 `sources/` 生成独立 `runtime/`，替换绝对路径并记录摘要。原始快照不变。runtime 已存在时拒绝覆盖，防止覆盖自己改过的配置。

`paths.server.json` 保留服务器现有数据/模型/检查点输入，但将原项目 results 输出引到本包 runtime/results。训练配置里的 output_folder/save_folder 代表新运行；若要评测已训练模型，须明确指向对应旧检查点目录，不能把新空目录当作已训练权重。

## 执行一个模块

```bash
python pipeline.py run <stage> -- <该脚本的参数>
python pipeline.py run --execute <stage> -- <该脚本的参数>
```

第一条只打印命令；第二条才执行。stage 原生参数保持原脚本定义，不使用 shell 拼接。配置参数中的相对路径以 runtime 为工作目录。训练/解码之前先核对输入、输出和完整评测规模；演示时可在原生 CLI 中显式限制样本。

## 导出 GitHub 准备包

`python pipeline.py export --out /tmp/code_release.zip`

导出只读 `release_files.json` 白名单，不递归打包工作目录。模型、数据、预测、runtime、机器路径映射与来源绝对路径审计未放入白名单。源代码历史绝对路径仍在，可由 prepare 统一映射；因此这是可继续整理的代码包，不宣称匿名化或完全开箱即复现。

README 中保留作者/上游来源说明。尚未擅自选择代码许可证；正式公开时确认各文件来源与可采用的许可证，再加入相应文件。版本环境见 `docs/环境与依赖.md`，本次只进行 CPU 验收，不表示 GPU 全流程已经重跑。

## 第二篇示例（显式提供自己的文件路径）

```bash
python pipeline.py run filter -- --input /path/pseudo.csv --out /path/filtered.csv --quantile 0.80 --max-cr 2.4 --max-tps 20
python pipeline.py run memory -- --pool-csv /path/filtered.csv --lang kk --all --out /path/new_datastore
python pipeline.py run index -- --ds /path/new_datastore --out /path/new.index --nlist 2048 --m 64 --nprobe 32 --seed 0
python pipeline.py run decode -- --split dev --limit 0 --ds /path/new_datastore --index /path/new.index --lambda 0.4 --k 4 --T 100 --out /path/dev.json
```

这些是命令结构示例，最后一条尚未填入对应实验的完整保护参数，不能直接用来声称复现论文主表。使用 `run --execute <stage> -- --help` 查看原生参数时，部分脚本会导入 GPU 依赖；默认 list/verify/demo 不需要这些依赖。
CPU 汇总脚本按原项目布局读取 results；整理包没有复制大量预测结果。原实验复核可继续使用原 notes 路径，独立运行需把需要的结果复制/链接进 runtime 并核对脚本输入清单。
